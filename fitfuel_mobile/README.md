# FitFuel Mobile

Flutter conversion of the FitFuel Stitch UI kit (16 screens) into a real,
running Flutter app — same layout, colors, type scale, and logo as the
original Stitch export.

## What's here

- `lib/theme/app_theme.dart` — colors, type scale, spacing, shadows, radii,
  1:1 with the Stitch "Vitality Tech-Aesthetic" design system.
- `lib/widgets/app_widgets.dart` — shared components (bottom nav, match-score
  chip, pill tab selector, macro progress rings, step progress bar, selectable
  cards/chips) reused across screens.
- `lib/screens/` — all 16 screens:
  splash, onboarding (3-slide carousel), login, register, health assessment
  (weight → activity → goals → prefs), plan ready, dashboard, recommendations,
  meal detail, weekly meal plan, progress tracking.
- `lib/services/` — `api_config.dart`, `api_service.dart` (thin HTTP wrapper
  with auth header + typed errors), `auth_service.dart` (register/login/token
  storage via `shared_preferences`).
- `lib/models/models.dart` — Dart classes mirroring the backend Prisma schema
  (`User`, `HealthProfile`, `Meal`, `Order`, `ProgressLog`).
- `assets/images/logo.png` — the actual FitFuel logo from the Stitch export.

## Notes on the conversion

- Typography uses `google_fonts` (Manrope for headings, Inter for body) since
  the Stitch export didn't include font files — this fetches the same fonts
  Stitch used, so the type scale matches.
- A few screens in the original Stitch HTML referenced external stock photos
  (Google-hosted URLs). Those aren't bundled assets, so those spots use
  icon-based decorative placeholders that follow the same layout and color
  treatment instead. Everywhere the FitFuel logo itself appears, it's the
  real asset from your upload.
- Screens are currently wired with mock/sample data so you can run and see
  the full UI immediately. `login_screen.dart` and `register_screen.dart` are
  already wired to `AuthService`; the rest (dashboard, recommendations, plan,
  progress) still need their `TODO`-free API wiring to your FastAPI backend
  endpoints from Tasks 1–13.

## Running it

This zip contains the Dart/Flutter source only (`lib/`, `assets/`, `pubspec.yaml`) —
the `android/` and `ios/` platform folders aren't included since they're
generated by the Flutter CLI, which isn't available in the environment this
was built in. Regenerate them in one step, then run normally:

```bash
flutter create . --project-name fitfuel_mobile   # generates android/ + ios/ in place, keeps lib/ and assets/
flutter pub get
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:4000   # Android emulator
# or
flutter run --dart-define=API_BASE_URL=http://localhost:4000  # iOS simulator
```
